# 企查查 Skill（qcc）

## 适用边界

用户问任何「某家公司怎么样 / 查企业 / 股东 / 风险 / 失信 / 中标 / 专利」等**企业事实类**问题，或点名企查查时，用本技能查实时数据。**不要用训练记忆或网络搜索回答企业事实**——那正是幻觉的重灾区（认错主体、用过时数据、编造股东）。

企业主体必须用**企业全称或 18 位统一社会信用代码**查询。用户给的名称模糊/有歧义时，先用工具返回的候选实体让用户确认，宁可多问一句也不要查错主体。

## 主路径：qcc.py 脚本

本技能目录下 `qcc.py` 零第三方依赖，直连 agent.qcc.com 的 MCP 端点，用 `shell` 工具调用。

**脚本路径**：
- 容器内：`/root/.ethan/skills/qcc/qcc.py`
- 本机：`~/.ethan/skills/qcc/qcc.py`

**鉴权**：自动读取 `~/.ethan/.secrets/qcc-api-key`（内容 `QCC_AUTHORIZATION=Bearer <token>`）。报 invalid_token 时提示用户更新该文件。

### 子命令

```bash
# 1. 列出全部 server（10 个）
python3 qcc.py servers

# 2. 列出某 server 的工具（含参数名与说明，找工具用这个）
python3 qcc.py tools risk
python3 qcc.py tools company --full   # 完整说明（工具 description 里有重要的使用纪律）

# 3. 调用工具（--args 传 JSON）
python3 qcc.py call company get_company_registration_info --args '{"searchKey": "小米科技有限责任公司"}'
python3 qcc.py call risk get_serious_violation --args '{"searchKey": "小米科技有限责任公司"}'
python3 qcc.py call company get_shareholder_info --args '{"searchKey": "..."}' --no-cache  # 强制实时
```

### server 一览

| server | 内容 |
|--------|------|
| `company` | 工商登记、股东、实控人、受益所有人、主要人员、对外投资、财务 |
| `risk` | 失信、被执行、限高、严重违法、裁判文书、立案信息、行政处罚等红线 |
| `operation` | 招投标、资质荣誉、新闻舆情、纳税资质、招聘等经营动态 |
| `ipr` | 商标、专利、软著、作品著作权、APP/公众号等数字资产 |
| `history` | 历史股东/法代/失信/投资（识别"洗白型"主体；需企业认证） |
| `executive` | 董监高个人司法风险、关联企业、UBO（参数=企业名+人名） |
| `regulation` | 法律法规检索（法条级正文、时效标注） |
| `case` | 司法案例/类案检索 |
| `tender` | 招投标标讯搜索、企业中标查询 |
| `document` | 在线 URL 文档智能解析（本机文件请直接 file_read） |

常用工具速查：`get_company_registration_info`（工商）、`get_shareholder_info`（股东）、`get_actual_controller`（实控人，已聚合穿透值，**禁止自己乘比例重算**）、`get_beneficial_owners`（受益所有人）、`get_serious_violation`（严重违法）、`get_dishonest_executor`（失信）。没把握就用 `tools <server>` 现查。

## 本地缓存（自动，省积分）

脚本对带 `searchKey` 的查询自动做文件缓存，**无需手动管理**：

- 路径：`~/.ethan/data/qcc/<公司名>/<server>.<tool>_<YYYY-MM-DD>.md`
- 查询前自动翻缓存：**30 天内**的结果直接命中返回，不调接口
- **超过 30 天视为过期**：自动重新调实时接口，并把新结果按当天日期写盘（旧文件保留作历史存档，文件名即查询日期）
- 缓存命中时输出头部会标注 `[qcc 缓存命中]` 和查询日期——**引用数据时以缓存标注的查询日期为准**，别说过期数据是"今天查的"
- 怀疑数据要求最新（如用户说"现在/刚刚/最新"）→ 加 `--no-cache` 强制实时

## 积分纪律（重要）

接口按积分计费（注册赠 500 + 每日赠送；**同一被查主体每自然月有消耗上限：个体工商户 20 / 企业 100 / 董监高 100 积分**）。因此：

1. **先缓存后调用**：默认行为已保证；同一公司同一维度不要短期内反复实时调用。
2. **按需选工具**：查"有没有失信"就调失信工具，不要为了一个问题把全维度都跑一遍。
3. **不要盲目翻页**：部分工具支持翻页但翻页额外扣积分，返回的"摘要 + 最近 N 条"通常足够决策。
4. 返回"经全量核查未发现 XX 记录"是**强语义负向结果**（= 确实没有），不是查询失败，不要重试。

## 输出引用纪律

- 比例/金额/案号等数字**逐字引用返回值**，禁止自行换算、四舍五入或拼凑。
- 公开未披露的字段如实说"未披露"，不要编。
- 给结论时注明数据来源与查询日期（缓存文件头里有）。
