# 人物档案格式（people profile）

一人一档，标题 `人物 - {名字}`，存知识库。档案分两部分：**画像头**（相对稳定的身份/关系/特点）+ **时间线**（按月按日的事件流水）。

## 存储

- 标题：`人物 - {名字}`
- tags：`["people", "{名字}", "{关系标签}"]`，关系标签取 `colleague` / `friend` / `family` / `partner`（合作方）/ `other`
- scene：同事/工作关系 → `work`；朋友/家人/生活关系 → `life`
- 写入只用 `knowledge_add` / `knowledge_edit`（见 SKILL.md R1）

## 档案结构

```markdown
> 关系：同事（直属下属）
> 方向：支付 / 交易基础架构
> 认识于：2024-03
> 联系方式：（可选，飞书 open_id / 微信等）

## 画像
- 技术扎实，做事较真，code review 很细
- 喜欢滑雪，家在深圳

---

# 2026-07

## 07-21
- [亮点] 完成支付模块联调，性能提升 30%（14:30）
- 参加了周会（10:00）

## 07-20
- 提出重构库存查询方案，被采纳（10:00）

---

# 2026-06

## 06-28
- 换到支付组（约上午）
```

### 各部分规则

**画像头**（`>` 引用块 + `## 画像`）：
- `> 关系`：必填，一句话说清 ta 和用户的关系
- `> 方向` / `> 认识于` / `> 联系方式`：可选，有就写
- `## 画像`：相对稳定的特点、偏好、背景。是"印象"就照实写印象，别当成事实断言。随了解加深可增删。

**时间线**（`# YYYY-MM` → `## MM-DD` → `- 事件`）：
- `# YYYY-MM`：月份标题，**倒序**（最新在上），月份间用 `---` 分隔
- `## MM-DD`：日期标题，月内倒序
- `- 内容（HH:MM）`：一条一事，括号内为事件发生时间（不是记录时间），不确定可写"（上午）"或省略
- 空行：月份/日期标题前后、分隔线前后各留一个空行

### 事件标签（可选）

标签放内容最前，空格分隔。**朋友/家人档案通常不需要标签**，普通生活事件直接写。工作向档案可用：

| 标签 | 用途 |
|---|---|
| `[亮点]` | 突出表现、量化成果、主动承担（多由 team-manager 写入） |
| `[问题]` | 线上问题、质量缺陷、进度延期 |
| `[进展]` | 已记录事件的后续更新 |
| 无标签 | 普通事件（协作、会议、日常、生活近况） |

## 新建档案模板

首次为某人建档，`knowledge_add`：

- title：`人物 - {名字}`
- tags：`["people", "{名字}", "{关系标签}"]`
- scene：按关系判断
- content：
  ```markdown
  > 关系：{一句话关系}
  > 方向：{可选}
  > 认识于：{可选 YYYY-MM}

  ## 画像
  - {已知的第一条特点/背景，没有可留空这一段}

  ---

  # {YYYY-MM}

  ## {MM-DD}
  - {首条事件}（{HH:MM}）
  ```

建档后**务必按 SKILL.md R3 写一条 memory 指针**。

## 追加事件

`knowledge_edit`（先 read 全文，去重后 replace 写回，见 recall-and-dedup.md）：

1. 读全文，看顶部是否当前月份：
   - 是 → 找当天日期：有则在该日列表末尾追加；无则按倒序插入当天日期标题再追加
   - 否 → 顶部插入新月份标题 + 当天 + 事件，与旧月份间加 `---`
2. 若这条信息属于**画像级**（换了工作、搬家、稳定的新特点），更新 `## 画像` 段落而不是只记时间线；重要身份变化同步刷新 memory 指针

## 内容规则

1. **客观优先**：事件记事实（"完成了 X"、"换工作到 Y"）；主观印象放画像段并注明
2. **量化优先**：能用数字就用数字
3. **单条单事**：一条只记一件事
4. **名字一致**：同一个人统一用一个主名（别在"张三/老张/张工"间跳）；别名可写进画像
