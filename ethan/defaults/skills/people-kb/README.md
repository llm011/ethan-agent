# People KB（名片知识库 / 人物志）

在日常对话中被动感知你聊到的人——朋友、同事、家人、合作方——一人一档持续沉淀到知识库。日积月累，Agent 越来越懂你身边的人；再聊到某人时，自动把 ta 的档案捞回上下文。

> 数据写**知识库**（`scene` 区分 work/life），memory 里只放一句话「指针」用于召回。人物档案会越来越大，所以不塞进 memory。

## 三件事

### 1. 被动记录

不需要你显式说"记一下"。只要对话里出现**一个具体的人 + 一条关于 ta 的信息**，Agent 就把它沉淀进 `人物 - {名字}` 档案：

- 身份/关系：「我同事张三」「我大学室友小林」
- 做了什么：「张三今天把支付联调搞定了」「小林换工作了」
- 特点/近况：「张三特别较真」「李姐孩子刚上小学」

### 2. 召回

再聊到这个人时，Agent 先从 memory 召回一句话指针（知道"这是你认识的人"），再 `knowledge_search` 拉全量档案补进上下文。问「张三最近怎么样」也走这条路。

### 3. 去重与定期整理

按月去重，避免同一件事记多次。建议配一个每月的定时任务，合并重名档案、清理碎片、刷新画像。

## 存储

一人一条知识库条目：

| 字段 | 值 |
|---|---|
| 标题 | `人物 - {名字}` |
| tags | `["people", "{名字}", "{关系}"]`，关系取 colleague/friend/family/partner |
| scene | 同事/工作 → `work`；朋友/家人/生活 → `life` |

档案结构：画像头（关系、方向、特点）+ 时间线（按月按日事件）。详见 `references/profile-format.md`。

## 关联技能

| 技能 | 关系 |
|---|---|
| `team-manager` | 绩效/CR/群扫描识别的工作事件写进人物档案时间线 |
| `schedule-manager` | 含人物的时间信号（生日、约饭）转交它建提醒 |

## 设计原则

- **朋友同事都记**：是"你认识的人"的知识库，不只是打工场景
- **低打扰**：信息明确就直接记 + 一句话确认，只在歧义时才问
- **隐私边界**：仅存本地知识库，不发外部
- **不臆造**：拿不准名字/关系先问
