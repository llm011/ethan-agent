# 音频脚本写作指南（book-audio-digest）

目标场景：用户早上出门开车、排队等时间间隙收听。脚本写进 `$PROJECT/manifest.json`，由 `scripts/audio_pipeline.py` 合成 MP3。

## 时长与篇幅

- 默认目标 **8–15 分钟**（`targetDurationSec` 480–900）。用户指定时长时遵从用户。
- 中文 TTS 常速约 **260–300 字/分钟**：10 分钟 ≈ 2800 字上下。validate 输出的 `estimatedChars` 可快速核对。
- 单节 narration 200–800 字（口语一口气说不完的长度就该切节），节数 6–14。
- 章节间由 `gapMs`（默认 700ms）静音分隔，形成听觉上的"段落感"。

## 结构模板（总-分-收）

1. **opening（冷开场，≤100 字）**：一句有钩子的话开场——用书中最扎心的一条划线、或一个直击用户场景的问题。禁止"大家好，今天给大家带来…"式套话。
2. **book-and-author（150–300 字）**：这本书讲什么、作者为什么有资格讲、为什么此刻值得听。
3. **insight-1..N（主体，每节 300–700 字，共 3–6 节）**：每节一个核心洞察，内部三段式：
   - 观点：用大白话先说结论
   - 佐证：引书中的划线原文（口语引入，如"书里有句话说得特别透——"）+ 简短解释
   - 关联：结合知识库里的个人内容（如有）或常识场景，说"这对你意味着什么"
4. **closing（≤150 字）**：一条可带走的行为建议 + 一句收束。不做"总结陈词"。

## 口语化铁律

- **说人话**：短句为主，一句一个意思；长复合句拆开。"综上所述""值得注意的是"这类书面连接词全删。
- **人称用"你"**：像跟一个人聊天，不是广播。"我们来看"可以，"读者应当"不行。
- **数字口语化**："24%"读作"百分之二十四"；大数字换算（"3.2 万人"→"三万多人"视语境）。
- **不念标点、不念格式**：没有"第一点、第二点"式列表腔；过渡靠内容和语气，不靠"接下来"。
- **引用原文要消化**：热门划线直接引用 ≤ 15% 篇幅，每次引用前必须有口语引入，引用后必须有自己的解读。
- **开头三秒定生死**：第一句必须是具体内容（金句/问题/反常识判断），不是自我介绍。

## 声音选择（voice.name）

| 声音 | 特点 | 适用 |
|------|------|------|
| `zh-CN-YunxiNeural`（云希，默认） | 沉稳男声，知识播报感 | 大多数非虚构/认知类书 |
| `zh-CN-XiaoxiaoNeural`（晓晓） | 标准女声，亲和 | 亲子/生活/情感类 |
| `zh-CN-YunyangNeural`（云扬） | 新闻播报腔，字正腔圆 | 时事/传记类 |
| `zh-CN-XiaoyiNeural`（晓伊） | 年轻女声，轻快 | 轻松话题 |

语速：`rate` 默认 `+0%`；内容密度高可 `-5%` 放慢，资讯类可 `+5%`。用户有偏好时遵从用户。

## manifest 校验清单

- [ ] 所有 id 唯一且 kebab-case（如 `insight-1`、`closing`）
- [ ] narration 无 Markdown 语法（`**`、`#`、链接）——TTS 会照念
- [ ] estimatedChars ÷ 280 ≈ targetDurationSec/60（偏差 > 20% 先调文字）
- [ ] title 格式 `《书名》深度听书`
- [ ] 知识库关联 ≤ 2 条且已融入行文（不是生硬插入）

## 常见失败与处置

- **Edge TTS 空音频/超时**：脚本自动重试 3 次；仍失败检查网络（代理未运行时用 `env -u HTTP_PROXY -u HTTPS_PROXY ...` 直连）
- **时长超 target ±40%**：改脚本文字量重跑；章节 id 不变的部分命中缓存，秒级完成
- **语速听起来不对**：调 `rate` 后重跑——voice 进缓存键，会自动重新合成
