# 飞书深度读书笔记结构指南（book-audio-digest）

产出文档用 `lark-cli docs +create --as user` 创建（owner 必须是用户）。排版铁律遵循 feishu-writer 技能（黄金开局、去 AI 味、Callout 节制、表格 `<colgroup>` 总宽 ~780）；本文档只定义**读书笔记的内容结构**。

## 篇幅底线

深度解读 ≥ 2500 字，H2 章节 ≥ 4。音频脚本就是从这篇笔记口语化改写来的，笔记的深度决定音频的深度。

## 文档结构

```
H1：《书名》深度解读 — 副题（一句话点出这本书对读者意味着什么）
元信息表格：书名/作者/微信读书评分/预计阅读时长/生成时间
📌 背景摘要 Callout（≤3 句）：这本书解决什么问题，读完了解什么

## 这本书在说什么（为什么是现在读）
作者背景与资格 → 全书主线 → 章节结构速览（可配全书脉络 Mermaid 图，节点双引号包裹）

## 核心洞察（每条一个 H3 或独立 H2，3–6 条）
每条固定三层展开：
- 原文锚点：引用 1–2 条高热度划线（注明划线人数，用引用块）
- 深度解读：这句话背后作者的逻辑链，与常识的冲突点
- 个人关联：结合知识库内容/个人场景的感悟（知识库素材在这里用，注明来源笔记）

## 读者画像与适配
什么样的人此刻最需要这本书；什么情况下不值当读（诚实说边界）

## 三个可带走的行动
具体到"本周就能做"的行为，不写"保持开放心态"这类空话

✅ 核心结论 Callout（3 条以内）
相关链接：微信读书 deepLink / 相似书推荐
```

## 写作纪律

- **划线即民意**：热门划线的 totalCount 是读者用手指投票的结果，解读优先围绕高热划线展开；但别被热度绑架——低热但构成全书骨架的观点也要覆盖。
- **去重聚类**：跨章节重复出现的划线合并成一个主题，同义划线只引最热的那条。
- **个人感悟必须有**：没有知识库关联时，也要基于书的内容给出"所以呢"——这条洞察改变了什么行动/认知。纯复述=没做完。
- **不虚构**：书里没有的数据、案例、结论一律不写。拿不准的写"书中未展开"。
- **评分与热度数据**注明来自微信读书，引用划线标注划线人数（如"1.2 万人划线"）。
