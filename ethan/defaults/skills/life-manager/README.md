# Life Manager

个人工作与生活的记录、管理与提醒助理。把零散信息沉淀进知识库，让 Agent 帮你盯时间节点和交付。

> 数据统一写入**知识库**（`scene` 区分 `work`/`life`），后端可在 filesystem / Obsidian / external 间切换。
> 时间线和定时任务管理由 `schedule-manager` 技能负责。本技能专注「记录 + 识别 + 提醒」。

## 适用场景

希望 Agent 帮你处理工作与生活中各类记录、文档、提醒事务的人。不只是团队管理——还包括项目进展、文档收藏、工作沉淀整理，以及从对话中识别时间信号自动建议提醒。

## 五大能力

### 1. 人员/团队管理

平时持续收集成员工作事件，绩效季汇总评估并生成建议。

**信息来源**：手动记录 / 文档分析 / CR 统计 / 群消息提取（定时任务由 schedule-manager 创建）

### 2. 事情/项目/文档管理

- **项目进展** — 按业务+项目记录进展，含时间节点（可触发提醒）
- **业务范围** — 维护业务方向和关注仓库
- **文档收藏** — 解析链接自动收藏，front matter 保留 source
- **工作沉淀整理** — 把同事的文档按分类整理进知识库

### 3. 知识库统一入口

所有记录通过 `knowledge_add` / `knowledge_search` / `knowledge_read` / `knowledge_edit` 读写，scene 区分 work/life。后端切到 Obsidian 时数据自然出现在 vault 的对应子目录。

### 4. 定时信号识别（核心）

从对话/电话/妙记/文档/口述中识别时间节点和待办信号，主动列出候选，用户确认后调 `schedule_create` 创建提醒。

**信号来源**（别只盯对话文字）：
- 用户直接发的消息
- **电话/通话录音转文字**（"刚才电话里说..."、"通话记录里提到..."）
- **飞书妙记/会议纪要**（用户转来 minute_token 或妙记链接）
- 拉取的飞书文档、网页内容
- 口述转写（语音消息、口头交代）

**信号类型**：明确日期 / 相对时间 / 周期性 / 待办动词+时间 / 隐式截止

**流程**：识别 → 列出候选（含置信度、来源）→ 用户确认 → 创建提醒 → 回复确认

### 5. 提醒与自动化

主动追踪项目节点、交付截止、例行巡检，到点自动提醒。

- 项目节点提醒 — 进展中记录的时间节点到点前主动提醒
- 交付截止提醒 — 任务 DDL 前 1 天/当天自动提醒
- 例行巡检 — 每日晨间扫描项目进展，发现延期风险预警
- 绩效季提醒 — 绩效季临近时主动提醒收集数据

## 快速开始

### 1. 安装

重启 Ethan Agent 即可，技能会自动同步到 `~/.ethan/skills/`，`~/.ethan/work/` 目录及配置文件也会自动创建。

### 2. 配置团队

编辑 `~/.ethan/work/team.yaml`，填入团队信息：

```yaml
self:
  name: "张三"
  role: "前端负责人"

members:
  - name: "李四"
    role: "高级工程师"
    direction: "基础架构"
    joined: "2024-03"
    code_username: "lisi"
```

### 3. 开始使用

直接用自然语言触发：

| 场景 | 示例 |
|---|---|
| 记录事件 | 「记一下，小王今天主动排查了线上问题」 |
| 文档分析 | 「帮我看看这个文档」+ 转发链接 |
| CR 统计 | 「帮我看下这周的 CR 汇总」 |
| 任务委派 | 「安排一下小王，设计插件架构，下周五前出方案」 |
| 工作沉淀整理 | 「整理下范文杰的工作沉淀，分类写入，记得链接别搞丢了」+ 链接 |
| 群监控 | 「帮我监控这个群，每天扫一次」 |
| 绩效汇总 | 「帮我汇总下这季度的绩效」 |
| 定时信号识别 | 「下周五前完成 xxx，每月 15 号提醒我交报表」 |
| 电话信号识别 | 「刚才电话里跟 A 同步了 8.15 要交付 xxx」 |
| 妙记信号识别 | 「这是刚才会议的妙记，看看有没有时间节点」+ minute_token |
| 项目节点 | 「这个项目 8.15 要完成 xxx，到时候提醒我」 |
| 生活记录 | 「记一下周末要陪家人体检」 |

## 数据存储

所有数据通过 knowledge_* 工具读写，scene 区分 work/life。后端切到 Obsidian 时数据自然出现在 vault 的 `work/` 或 `life/` 子目录下。

**条目类型**：

| 类型 | 标题格式 | tags | scene |
|---|---|---|---|
| 人员日志 | `人员日志 - {姓名}` | `["people", "{姓名}"]` | work |
| 项目进展 | `项目进展 - {业务名} - {项目名}` | `["project", "{业务名}", "{项目名}"]` | work |
| 业务范围 | `业务范围 - {业务名}` | `["scope", "{业务名}"]` | work |
| 文档收藏 | `文档收藏 - {文档标题}` | `["doc", "{业务名}", "{分类}"]` | work/life |
| 工作沉淀 | `{姓名}工作沉淀 - {分类名}` | `["doc", "people", "{姓名}", "{分类名}"]` | work |
| CR 周报 | `CR周报 - {业务名} - {YYYY}-W{NN}` | `["cr-report", "{业务名}"]` | work |
| 绩效草稿 | `绩效草稿 - {YYYY}-Q{N}` | `["review", "{YYYY}-Q{N}"]` | work |
| 个人事项 | `{主题}` | `["personal", "{分类}"]` | life |

**配置文件**：`~/.ethan/work/team.yaml`（团队信息，不走知识库）

### Front Matter 约定（Obsidian 后端）

- 固定字段：`title` / `type` / `tags` / `created` / `updated`（后端自动管理）
- 扩展字段：通过 `frontmatter` 参数传入，模型按需补充
  - 内容来自外部网页/文档时，必传 `{"source": "{url}"}` 记录原文链接
  - 可追加 `author`、`published` 等字段，字段名小写、值用字符串
- filesystem 后端忽略 `frontmatter`，但参数仍要传

## 关联技能

| 技能 | 用途 |
|---|---|
| `schedule-manager` | 定时任务和时间线管理（任务提醒、周期编排、群扫描定时任务） |
| `lark-task` | 创建飞书任务和提醒 |
| `lark-im` | 发送提醒消息、扫描群消息 |
| `lark-doc` | 读取文档内容分析 |
| `lark-calendar` | 评审/对齐日历事件（可选） |
| `code-review` | CR 数据拉取与分析 |

## 设计原则

- **不做最终判定**：Agent 只提供汇总和建议，绩效打分由管理者决定
- **确认后再创建**：任务拆分、飞书任务、定时提醒的创建必须经用户确认
- **隐私边界**：所有数据仅存本地知识库，不上传外部
- **通用框架**：不含任何个人/公司/团队信息，开箱即用
- **写入工具约束**：所有数据写入只用 `knowledge_add` / `knowledge_edit`，禁止 `file_write` / `shell`
