# 定时信号识别（从任意内容里抠时间节点/待办）

这是一个**通用能力**：在任何对话/电话/妙记/文档/口述中识别时间节点或待办信号，列出候选，用户确认后 `schedule_create` 建提醒。people-kb / work-notes / team-manager 在处理内容时若发现时间信号，都转交到这里。

## 信号来源（别只盯对话文字）

- 用户直接发的消息
- **电话/通话录音转文字**（"刚才电话里说…"、"通话记录里提到…"）
- **飞书妙记/会议纪要**（转来的 minute_token 或妙记链接，走 `lark-minutes`）
- 拉取的飞书文档、网页内容
- 口述转写（语音消息、口头交代）

## 信号类型

- 明确日期：「8.15 前完成」「下周五交付」「10 月底上线」
- 相对时间：「下周三」「三天后」「月底」
- 周期性：「每天早上扫一下」「每周五汇总」「每月 15 号」
- 待办动词+时间：「提醒我下周三…」「记一下周五要…」
- 隐式截止：「这个项目 8.15 上线」（隐含到点要检查）

## 执行流程（先确认再创建）

### 1. 识别

从消息/文档抽取所有候选信号，每个提取：
- `{时间表达式}`：原文表述
- `{解析后日期}`：`YYYY-MM-DD HH:MM`（相对时间按当前日期推算，默认 `Asia/Shanghai`）
- `{事件内容}`：做什么/交付什么
- `{信号来源}`：对话/电话/妙记/文档/口述
- `{置信度}`：高（明确日期）/中（相对时间）/低（模糊如"近期"）

### 2. 列出候选

```
检测到 {N} 个时间信号：

1. 「下周五前完成 xxx」→ 2026-08-01 09:00 [高置信] [来源：对话]
   └ 建议创建：8.01 09:00 提醒
2. 「每周五下午扫一下群」→ 周期任务 [高置信] [来源：妙记]
   └ 建议创建：每周五 16:00 重复
3. 「近期整理一下」→ 时间模糊 [低置信] [来源：电话]
   └ 建议忽略或确认时间
```

### 3. 用户确认

问「要创建哪些？回复编号即可（如 1,2），或调整时间」。用户回编号 → 建对应；说"全部" → 全建；说"忽略" → 不建。

### 4. 创建提醒

对确认的信号调 `schedule_create`：
- 一次性 → `category="one_off"`，用具体日期的 cron
- 周期性 → `category="recurring"`，用周期 cron
- `scene` 跟随原信号场景

### 5. 回复确认

列出已创建的提醒（job_id、时间、内容），提示可后续修改或取消。

## 关键约束

- **必须先确认再创建**（除非用户明确说"自动创建"）
- 模糊时间（近期、尽快）不直接建，先问具体时间
- 识别要全面——即便用户主要意图是别的，只要含时间信号就主动列出
- 电话/妙记来源的信号，列出时标注来源方便核对
- cron 周几用名称（`mon-sun`），见 SKILL.md 约束
